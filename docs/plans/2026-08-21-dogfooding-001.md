# DOGFOODING-001: Algorithmic Code Hardening Loop — Auto-Auditoría y Recursividad

## 1. Problem Statement
Validar la auto-consistencia, hermeticidad y completitud del framework **Algorithmic Code Hardening Loop** ejecutando el método de 5 fases sobre su propia base de código (`src/`, `schemas/`, `tests/`, `docs/spec_v0.1.md`).

El objetivo no es verificar "si corre", sino auditar:
1. **Soporte de Targets Multivariable/Directorios:** Capacidad de computar hashes deterministas agregados (Merkle/árbol) sobre directorios completos y no solo archivos individuales.
2. **Hermeticidad y Reproducibilidad:** Garantizar que dos corridas sucesivas (`run-A` y `run-B`) sobre el mismo estado del árbol produzcan idénticos hashes de payload y veredictos (eliminando drift por timestamps).
3. **Evolución de Schemas vía Knowledge Admission Gate:** Descubrir faltantes reales (ej: `method_version`, `environment_hash` en `EvidenceEnvelope`), pasar el hallazgo por la Aduana y aplicar el upgrade normativo sin romper compatibilidad.
4. **Tests de Invariantes vs Tests de Implementación:** Elevar la suite de tests a verificaciones ontológicas del sistema (invariantes de seguridad, imposibilidad de bypass de aduana).
